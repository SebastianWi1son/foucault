### Q2 — 从门面开始，解释各函数的作用

**门面全文 33 行**，三处结构比函数本身更重要：

```cpp
template <typename Solver = solver::Mahony>          // ① 编译期策略（F13），零开销
class Estimator {
public:
    explicit Estimator(Dimension dim = Dimension::d3) // ② 配置翻译
        : solver_(make_mahony_config(dim)) { }        // ②' ⚠️ 写死 Mahony（P0-1）
    void predict(const measure::IMUSample& s, float dt) { solver_.predict(s.gyro_, dt); }
    void observe(const measure::IMUSample& s, float dt) { solver_.observe(s.acc_,  dt); }
    void observe_heading(float, float) { }                // ⑤ 空实现（预留）
    void reset() { solver_.reset(); }
    void reset(const math::Quatf& q) { solver_.reset(q); }
    const math::Quatf& quaternion() const { return solver_.quaternion(); }
    math::Vec3f euler() const { return solver_.euler(); }
private:
    Solver solver_;                                   // ⑩ 唯一成员 → 门面自身零状态
};
```

| 函数 | 作用 | 关键点 |
|---|---|---|
| `Estimator(Dimension)` | 把"数学维度档位"翻译成求解器参数 | 消费者只该说"我是平面运动"，不该知道 `Kp=5` |
| `predict(s, dt)` | 时间推进；只取 `s.gyro_` | 首个量测前 `is_meas_=false` → 纯积分 |
| `observe(s, dt)` | 量测更新；只取 `s.acc_` | **不改变 `q_`**，只备料 |
| `observe_heading(y, dt)` | 外部航向注入口 | 空实现；调用它会被**静默忽略**（无标志） |
| `reset()` / `reset(q)` | 回上电态 / 指定初始姿态（F5） | `reset(q)` 先 `normalize` 防御 |
| `quaternion()` | const 引用，零拷贝 | `q` 把机体系向量转到世界系 |
| `euler()` | 值返回 (roll,pitch,yaw) 弧度 | 内旋 ZYX；欧拉角只在输出层转换 |

**一次生命周期**：

```
构造 → (可选)reset(q0) → 循环{ observe(备料) → predict(下锅) } → 读 quaternion()/euler()
```

**门面不负责什么（边界归属）**：输入校验/仲裁 → `measure/`（不存在）；坐标系约定 → 藏在 `mahony.cpp:38`；品质标志 → `output.h`（不存在）；时间戳管理 → 调用方。

**三个最容易踩的误解**：

| 误解 | 事实 |
|---|---|
| `predict` = 纯陀螺积分 | 错，含 Mahony 的全部修正 |
| `observe` 会更新姿态 | 错，只准备修正量 |
| `Estimator<Solver>` 真能换算法 | 现在不能（P0-1） |

### Q3 — 检查架构图（canvas）对不对

原 canvas 的流程（视觉从右往左）：`omega_sensor → solver_ → omega → q(t)' → q_k+1 → q_current`，另有一条 `矫正器(Acc/Odom/Mag) → solver_`（标 "guide"）。

**骨架对**（主链与 `Mahony::predict` 真实执行顺序一致，`omega_sensor`/`omega` 两节点精确对应原始陀螺与修正后角速度），但：

**必须修（3 处）**

| 编号 | 问题 | 后果 |
|---|---|---|
| E-1 | **闭环断了**：`q_current` 只有入边、无出边 | 它必须是 ①`q̇=½q⊗ω` 的左乘因子 ②矫正器算残差 `h(q̂)` 的输入。**没有 q̂ 就没有残差** → 图把闭环滤波器画成了开环校正器 |
| E-2 | **E1 箭头起点错**：`q(t)' → q_k+1` 但标签写 `q_k+1 = q_k + delta_q` | 积分有两个输入（`q_k` 与 `q̇·dt`），画成"导数单独生成状态"，公式与箭头对不上 |
| E-3 | **缺 normalize 节点** | `quat.hpp:62` 就是 `return normalize()`；DESIGN §1.5 称"积分后必须做的一步"。这条链上最不能漏的一步 |

**结构性缺失（2 处）**

| 编号 | 问题 |
|---|---|
| E-4 | `solver_` 一个盒子吞掉两个语义（`observe` 备料 / `predict` 下锅），看不出"observe 不改姿态"与 F4 异步多速率 |
| E-5 | `b̂`（零偏估计 `Ki·∫e`）自己的回路没画；`"guide"` 标签信息量为零（违反命名框架①） |

**标注缺失**：坐标系（机体系 vs 世界系 z-up）、单位（rad/s、秒）、**现役 vs 预留**（Acc 现役 / Odom·Mag 未实现）、产品配置（磁力计大概率没有，不该与 Acc 并列）。

**记法问题**：`q_current`/`q_k`/`q(t)` **三套记法混用**；`q(t)'` 撇号非标准（应为 `q̇`）；`solver_` 是代码成员名混进数学图。

> **修正方案**（Q4 已实施）：主链左→右；补 `q̂ → observe` 回授边；合并"导数+积分"为一个节点（代码本就是一步）；删 `omega_sensor` 改用代码名 `gyro`；每节点固定三行 **物理 → 数学 → 代码（文件:行）**；颜色区分 物理/算子/状态/预留。

## 2. 核心：`predict`

### Q5 — 讲讲 `predict`

**定位**：`predict` 是**唯一改变 `q_` 的函数**。它干两件事——① 把量测修正折进角速度；② 用这个角速度把姿态往前推 `dt` 秒。

```cpp
23| void Mahony::predict(const math::Vec3f& gyro, float dt) {
24|     math::Vec3f omega = gyro;              // 拷贝一份（gyro 是 const 引用，不能改）
25|     if (is_meas_) {                        // 门禁：没收到量测就不修正
27|         omega.x_ += cfg_.kp_ * e_last_.x_ + cfg_.ki_ * e_int_.x_;   // ω_c = ω + Kp·e + Ki·∫e
28|         omega.y_ += ...
29|         omega.z_ += ...
30|     }
31|     q_.integrate(omega, dt);               // ★ 传的是 omega，不是 gyro
32| }
```

**数学**（第一项）：

```
q̇ = ½ · q ⊗ (0, ω)        ⊗ 是 Hamilton 积；ω 必须写为纯四元数 (0,ωx,ωy,ωz)
```

| 要点 | 说明 |
|---|---|
| **右乘 = 机体系** | 代码是 `q ⊗ (0,ω)` → 喂进来的 **`gyro` 必须是机体系**。喂世界系要改成左乘 `ω ⊗ q`；**喂错会静默发散，不报错** |
| **½ 从哪来** | 四元数与旋转矩阵是二次关系，微分一次掉出 2 |
| **Mahony 的技巧** | 把修正项折进 ω：`ω_c = ω_meas + Kp·e + Ki·∫e`。因为"对姿态做小修正"与"给角速度加一点量"在四元数代数里是同一件事 |

**离散化（名义一阶欧拉）**：`q_{k+1} = normalize(q_k + q̇·dt)`，每步截断误差 O(dt²)。⚠️C1

**三个细节**：
- 第 24 行拷贝 `omega` 是"折进角速度"这一招的载体；也是 Mahony 与"纯陀螺积分"的**分界线**
- 第 25 行 `if (is_meas_)` **现在是个空守卫**（`reset()`/构造都把 `e_int_`/`e_last_` 清成 0，加 0 等于没加）。价值是**把语义写明**，并区分两种启动路径：先 `observe` 则首帧就带修正；先 `predict` 则纯积分（F5 运动自收敛）
- 三轴手写展开无循环（嵌入式风格）；代价是以后加 9 轴/维度模式会重复

**手算验证**（`q=identity`, `ω=(0,0,1)`, `dt=0.02`, 无修正）：

```
half = 0.01
n3 = 0 + (1×1 + 0 − 0)×0.01 = 0.01
→ q = (1,0,0,0.01) → normalize → (0.99995, 0, 0, 0.01)
→ yaw = atan2(2×0.0099995, 1−0.0002) ≈ 0.0200 rad = ω·dt ✓
```

**没做的事**：`dt` 不校验（0/负/NaN）；`gyro` 不校验；无坐标系守卫；积分精度固定为名义一阶欧拉。⚠️C1

### Q6 — `q_{k+1}` 是"此刻的最终姿态"还是"predict 的下一时刻四元数"？

**最关键的澄清：只有一个变量 `q_`。** `q_k` / `q_{k+1}` 不是两个变量，是**同一块内存里那个变量在两个时刻的值**。

`q_` 全项目只被三处写过：

| 谁写 | 写成什么 | 位置 |
|---|---|---|
| `reset()` | 单位元 | `mahony.cpp:9` |
| `reset(q)` | 指定初始姿态 | `mahony.cpp:17-18` |
| `predict()` → `integrate()` | **原地覆盖**（`q0_ = n0; ...`） | `mahony.cpp:31` → `quat.hpp:61` |

**答案有两层**：

| 问法 | 答案 |
|---|---|
| 它描述**哪一刻的物理姿态**？ | **下一时刻 `t_k + dt`**，不是 `t_k` |
| 它是程序里"最终定稿"的值吗？ | **是**。`predict` 返回后它就是最新值，读 `quaternion()` 读到的就是它 |

**两个"此刻"的歧义**：数据的此刻（`t_k`）vs 程序的此刻（`predict` 刚跑完）。

**为什么会觉得该有两个？因为下意识用了 EKF 的"先验/后验"模型**：

```
EKF（批次 4）:  predict → q̄（先验）  →  update → q̂（后验）   ← 两个变量
Mahony（现在）: predict（内含修正）  →  q_                    ← 只有一个
```

Mahony 只有一个，是因为**修正被折进了 ω**，不再需要单独一步改姿态。→ **等 EKF 上来时这个区分会出现**，`q_{k+1}` 要拆成 `q̄`/`q̂`，命名要提前准备。

**实验验证（含诚实修正）**：把回放 CSV 的真值平移 k 个样本再算 RMSE（15999 帧）：

```
k=0   (+0.00s)  roll 2.152°   pitch 2.645°
k=+1  (+0.02s)  roll 2.121°   pitch 2.630°
k=+10 (+0.20s)  roll 2.004°   pitch 2.551°  ← 最低点
```

⚠️ **修正**：初次解读时判为"偏移真实存在"。后查参考库（见 Q15）确认**参考库用的是同一约定**（`Run(row_i)` 与 `groundtruth(row_i)` 直接比），且 k=0→k=+1 仅改善 0.031°，远小于 k=+10 的 0.15°，**不具备"一拍时序偏移"应有的尖峰形状** → 判为**不显著**，该条已降级。

**实验结论（可复用的方法论）**：代码是权威——`integrate(ω, dt)` 把状态推进了 dt，所以 `predict` 后 `q_` 代表 `t + dt`。回放评估在 **k=0 约定**下与参考库一致。**将来做多算法精度对比时必须统一约定**，否则比的是时序而非算法。

### Q7 — "predict 出来本质是下一时刻的预测值，但我们把它当作此刻的 body 姿态"，对吗？

**半对。精确说法是：**

> **不是"我们把预测值当成此刻"——而是"它本来就是此刻，只要你把 `dt` 定义成『从上一帧到此刻』"。**

`predict` 只做"把 `q_` 沿 ω 前进 `dt` 秒"，**它自己不带时间戳**。时间标签由你喂的 `dt` 决定：

| `dt` 的含义 | `predict` 后 `q_` 对应 | 该跟谁比 |
|---|---|---|
| 「上一帧 → 这一帧」（向后看） | **这一帧 `t_i`** | `gt[i]` ✓ 就是"此刻" |
| 「现在 → 下一帧」（向前看） | `t_i + dt` | `gt[i+1]`（领先一拍） |

**真实项目推荐用法**（**predict 在前、observe 在后**）：

```cpp
float dt = (now_us - last_us) * 1e-6f;   // 用真实时间戳，别假设固定周期
est.predict(s, dt);                       // 把姿态从"上一帧"推到"此刻"
auto q = est.quaternion();                // ★ 此刻它 = 此刻的 body 姿态，直接喂控制环
est.observe(s, dt);                       // 备料，给下一帧的 predict 用
```

回放里是反的（observe 在前），所以它天然领先一拍——这正是 Q6 实验里 k=+1 略好的来源。

**"预测值"这个词要换掉**：

| 词 | 隐含意思 | 适用于 |
|---|---|---|
| **预测值 / 先验** | "只用陀螺积分、还没被量测修正过" | **EKF** |
| **当前最优估计** | "推演完、也修完，此刻我最好的估计" | **Mahony**（修正折在 ω 里，无"未修正"中间态） |

**与"措辞修正"的关联**（后续追问）：应修正为"**当前姿态的最优估计**"，而"作为此刻的**真实姿态**"要换成"作为此刻姿态的**工作值**"——因为它是估计不是真值，且**没有误差信息返回**（F8 缺失）。如果它真是"真实姿态"，`observe` 就根本不需要存在了。

### Q8 — `Quat::integrate` 的几何

**一句话**：**把这一帧转过的角度，叠加到当前姿态上。**

```cpp
54| Quat& integrate(const Vec3<T>& omega, T dt) {
55|     T half = T(0.5) * dt;
57|     T n0 = q0_ + (-q1_ * wx - q2_ * wy - q3_ * wz) * half;   // 这四行 =
58|     T n1 = q1_ + ( q0_ * wx + q2_ * wz - q3_ * wy) * half;   //   "q ⊗ (0,ω)" 的手写展开
59|     T n2 = q2_ + ( q0_ * wy - q1_ * wz + q3_ * wx) * half;
60|     T n3 = q3_ + ( q0_ * wz + q1_ * wy - q2_ * wx) * half;
61|     q0_ = n0; q1_ = n1; q2_ = n2; q3_ = n3;                  // 原地覆盖
62|     return normalize();                                      // ★ 必需，不是保险
63| }
```

| 步骤 | 内容 |
|---|---|
| ① 这一帧转了多少 | `ω·dt` 是**向量**：方向=转轴，长度=转过的**弧度**。例 `(0,0,1)×0.02 = 绕 z 转 0.02 rad ≈ 1.15°` |
| ② 变成四元数 | 旋转 θ 绕轴 û = `(cos(θ/2), û·sin(θ/2))`；θ 小时 `≈ (1, ½ω·dt)` |
| ③ 叠加 | `新姿态 = 老姿态 ⊗ 小旋转`。**右乘 = 机体系叠加**（gyro 是机体系读数，所以必须右乘） |
| ④ 代码就是③ | 精确恒等式：`q ⊗ (1, ½ωdt) = q⊗(1,0,0,0) + q⊗(0,½ωdt) = q + ½·q⊗(0,ω)·dt` |
| ⑤ 归一化 | `(1,½ωdt)` 是一阶近似，模长 `= √(1+¼|ω|²dt²) > 1`，**每步都乘一个略大于 1 的东西** |

**归一化的必要性（实测，去掉 normalize 跑）**：

| 场景 | 角速度 | 采样率 | 时长 | 模长漂到 |
|---|---|---|---|---|
| 地面小车 | 1.0 rad/s | 200 Hz | 300 s | **1.23** |
| 云台 | 17.4 rad/s（1000°/s） | 1 kHz | 60 s | **12.05** |
| 立体步兵 | 8.7 rad/s | 1 kHz | 60 s | **1.86** |

→ **三个目标场景全烂**。非单位四元数拿去 `rotate` 会让向量变形（`rotate` 公式只在单位四元数下成立）。

**为什么先算 `n0..n3` 再统一写回**：四个分量互相依赖（`n1` 用 `q0_`），边算边写会读到被污染的新值——典型的"原地更新污染"。

**精度**：一阶欧拉每步 O(dt²)。当前 `dt=0.02s` 容差仍宽松（roll RMSE 2.15°，误差主要来自加速度计动态污染而非积分精度）→ **暂不必升级 RK4**。⚠️C1（结论不变，但理由更强：量化后已是全局二阶）

### Q9 — `predict` 这个命名诚实吗？

**半诚实——根因很具体：这个名字是从一个没落地的设计里继承来的。**

`DESIGN.md §1.6` 的原始设计：

```
predict(gyro, dt)   —— 唯一固定的运动学          ← 纯外推
observe_vector(...) —— 6轴/9轴向量观测
observe_heading(...)    —— 外部航向注入
correct()           —— 增益求解器可插拔（算法差异只在这里）   ★

在那个设计下 `predict` **完全诚实**。**但 `correct()` 从未被实现**，因为 Mahony 把修正折进 ω，外推与修正在同一积分步里、物理上拆不开：

```

代码实现的:  predict（外推 + 修正，算法藏在这里面）
                                ↑ 名字没跟着改

**不是命名草率，是命名滞后于实现**——典型技术债。

**要补的文档**：

```
门面 predict 的语义 = 时间推进（time update），含该求解器自身的修正机制，不是"纯外推"。
门面 observe 的语义 = 量测更新（measurement update）。

## 3. 四元数基础

### Q10 — 四元数是"旋转动作的量"还是"姿态的量"？

**两者是同一个东西**——因为**姿态本身就是"一个旋转"**。

关键：**姿态不是绝对量，永远是相对于某个参考的**（"倾斜 30°"相对水平面；"yaw=90°"相对上电朝向）。所以：

```
机体系相对于世界系的姿态  ≡  "把世界系坐标转成机体系坐标"这个旋转
```

**但有三个"语义不同、类型相同"的四元数**：

| 代码里 | 表示什么 | 语义 | 跨帧存在 |
|---|---|---|---|
| `q_` | **累积的总旋转 = 姿态** | "现在板子朝哪" | ✅ **状态** |
| `r = (1, ½ωdt)` | **一帧内的微小旋转** | "这 20ms 转了多少" | ❌ 临时量 |
| `q ⊗ r` | **两个旋转的复合** | 姿态 + 增量 = 新姿态 | ❌ 计算结果 |

**微调你的说法**："四元数是旋转量，姿态是不断叠加得到的"——**对，而且这正是 `predict` 在做的事**。唯一要补的是：**叠加是"更新姿态"的手段，不是姿态的定义**。姿态在任意时刻都是"当前累积的总旋转"，它是一个**独立存在的状态**，不是动作。（类比："走了 3 公里"是状态，"走"是动作。）

### Q11 — `cos(θ/2), û·sin(θ/2)` 的第二项怎么变成 `½ω·dt`？

```
起点：旋转 θ 弧度、绕轴 û 的四元数 = ( cos(θ/2),  û·sin(θ/2) )
                                            ↑          ↑
                                        标量部分    向量部分

第 1 步：这一帧转过的角度  θ = |ω|·dt
第 2 步：ω 可写成"长度 × 方向"：ω = |ω|·û
        →  ω·dt = |ω|·û·dt = (|ω|·dt)·û = θ·û
        ★ 结论：ω·dt 这个向量本身就是"轴 û + 角 θ"
第 3 步：把第二项里的 θ 换成 ω·dt
        û·sin(θ/2)
          ≈ û·(θ/2)        ← θ 小时 sin(θ/2) ≈ θ/2（弧度制）
          = (θ·û)/2
          = (ω·dt)/2       ← 用第 2 步：θ·û = ω·dt
          = ½·ω·dt         ✓
```

**核心一句**：`û·sin(θ/2)` 里 `û` 是方向、`sin(θ/2)` 是长度；而 `ω·dt` **本身就是"方向 û、长度 θ"**，所以可互换。

### Q12 — Hamilton product 就是"旋转叠加"的计算方式吗？

**是的，这是它的核心用途（也是四元数被发明的动机）。**

```
q1 ⊗ q2   对应   "先施加 q2 的旋转，再施加 q1 的旋转"
数学上：  R(q1 ⊗ q2) = R(q1)·R(q2)
```

| 方式 | 复合两次旋转的代价 | 万向锁 |
|---|---|---|
| 欧拉角 | 要转矩阵或重算三角 | ❌ 有 |
| 旋转矩阵 | 3×3 相乘 ≈ 27 次乘法 | ✅ 无 |
| **四元数** | **一次 Hamilton 积 = 16 次乘法** | ✅ 无 |

**三个必须知道的限制**：

| 限制 | 说明 |
|---|---|
| **不可交换** | `q1⊗q2 ≠ q2⊗q1`。不是缺陷——**旋转本来就不能交换**（先绕 x 转 90° 再绕 y，与反过来不同） |
| **左右乘不同** | `q⊗r` = 在**机体系**叠加；`r⊗q` = 在**世界系**叠加。本代码用右乘（gyro 是机体系读数） |
| **只对单位四元数成立** | 非单位四元数的乘法代数上照样能算，但**不对应纯旋转** → 这就是要归一化的原因 |

另有一个不影响使用但值得知道的：**双覆盖**——`q` 与 `-q` 表示**同一个旋转**。

---

### Q13 — 那个等式记住就行吗？

**可以背，但要分开记哪一步"精确"、哪一步"近似"**（否则以后会以为公式写错了）：

```
新姿态 = 老姿态 ⊗ (这一帧的旋转)
       = q ⊗ ( cos(θ/2), û·sin(θ/2) )     ← ① 精确，但每帧要算 cos/sin（慢）
       ≈ q ⊗ ( 1, ½·ω·dt )                 ← ② 近似！丢掉 cos/sin 高阶项
       = q ⊗ (1,0,0,0) + q ⊗ (0, ½·ω·dt)   ← ③ 精确恒等式（乘法分配律）
       = q + ½·q ⊗ (0, ω) · dt             ← ④ 精确
       → normalize                          ← ⑤ 收拾 ② 的残留
```

| 步骤 | 性质 |
|---|---|
| ①② | ① 精确 / ② **近似** |
| ③④ | **精确**（代数恒等式） |
| ⑤ | **必需**（因为 ② 是近似） |

**"精确的代数 + 近似的物理"** = 一阶欧拉积分。⚠️C1

**记忆建议**：不背四条式子，**记住一个画面就够**——

> **新姿态 = 老姿态 ⊗ 这一帧的旋转，然后归一化。**

代码里那四行 `n0..n3` 只是 `⊗` 的手写展开（省掉一次函数调用）。

### Q14 — "只有单位四元数表示旋转"，那每次叠加都要对小旋转 normalize 吗？

**前提对（只有单位四元数表示旋转），但代码只归一化一次，且作用于"结果"。两种方案数学上都行。**

| 方案 | 写法 | 说明 |
|---|---|---|
| **A（代码用的）** | `q = normalize( q ⊗ (1, ½ωdt) )` | 小旋转非单位 → 乘积也非单位 → 必须归一化结果 |
| B | `q = q ⊗ normalize( (1, ½ωdt) )` | **单位 × 单位 = 单位**，理论上不用再归一化 |

**代码为什么选 A**：省事且不易漏（积分写成 `q += ...` 最自然，末尾统一一次）；两种方案都只要**一次**开方；B 略准但主导误差来自别处（加速度计动态污染），不值得多写。

**要记住的**：

```
★ 每步只归一化一次 —— 归一化的是"相乘之后的结果"，不是那个小旋转。
★ 这一步是必需的，不是保险（不做的话三个场景全烂，见 Q8）。
```

## 4. 工具与评估

### Q15 — `replay` 是做什么的？（此问源于"待办里的问题没理解"）

**replay = 把录好的真实数据重新"播放"一遍喂给算法，然后对答案。**

**它解决什么**：核心算法在桌面上**没法接真实 IMU**（手挥板子没法定量）。所以用**别人录好的数据集**——一长串 IMU 读数 **+** 每个时刻对应的真值姿态。

**类比**：

| 角色 | 是谁 |
|---|---|
| 考卷（题目） | 数据集的 acc / gyro 两列 |
| 标准答案 | 数据集的真值 euler 三列 |
| 考生 | 你的算法 core |
| 监考老师 | `host/replay/replay_nav2.cpp` —— 发卷、收卷、打分 |

**它具体做什么**（`replay_nav2.cpp`，136 行）：

```
1. load_dataset()   读文本 → 15999 行（acc3+gyro3+mag3+真值euler3）；50Hz → 320 秒
2. Estimator<> est; est.reset(初始 yaw = 真值)   ← 使评估的是"相对漂移"而非初始偏差
3. for (i = 0; i < 15999; i++) {          ★ 一帧一帧"播放"
       IMUSample s = {-acc[i], gyro[i]};  ← 坐标系适配（z-down → z-up）
       est.observe(s, 0.02f);             ← 备料
       est.predict(s, 0.02f);             ← 推进一步
       误差 = est.euler() - 真值[i];       ← ★ 对标准答案
       累计 误差²                          ← 用平方让负数不抵消
   }
4. RMSE = √(Σ误差² / 帧数)                ← "平均每帧差了几度"
```

当前结果：roll RMSE **2.152°** / pitch RMSE **2.645°** / yaw 漂移 **−14.450°**（6 轴下 yaw 不可观，预期行为，不判失败）。

**三个角色**：

| 角色 | 说明 |
|---|---|
| **自动验收** | `ctest` 第 4 个测试；`roll/pitch RMSE < 5°` 才算过——**唯一量化验收标准** |
| **回归测试** | 以后加 EKF/改参数，跑同一数据集对比，**立刻看出变好还是变坏** |
| **唯一跑真实数据的路径** | 另外三个 unit test 都只测人造场景 |

**一句话**：`replay` 是这个项目的**考试系统**。

**顺带查证（参考库）**：`reference/IMU_Attitude_Estimator/demo/Test.cpp` 用**同一约定**——`Mahony.Run(measurements.row(i))` 与 `groundtruth.row(i)` 直接比。且其 `deltaT` 也是构造时写死的 `0.02`。

**以及一个发现**：参考库的 **Ki 项失效**——`src/Mahony_Attitude.cpp:67-68` 把 `Vector_3 Integ_angular` 声明在 `else` 块内（每次调用重建），且第 68 行在赋值前就用它做右值；`Vector_3` = `Eigen::Matrix<double,3,1>`（`TypeDefs.h:14`）默认构造**不初始化**。→ 本库把 `e_int_` 作为**成员变量跨帧累加**（`mahony.cpp:43-48`）是**对参考库的修正**；也意味着**不能拿参考库数值当基准对齐**。

### Q16 — EKF 与 Mahony 在 `predict` 语义下有歧义，那"一体通用库的可插拔"是否有问题？

**判定：可插拔成立，但抽象层必须画在"数据进 / 结果出"，而不是"算法内部步骤"。**

> **答案已归档 `DESIGN.md §3.6`（该节正是由本次问答整理而成）+ `§5 F14`**：
> 3.6.1 存在性证明（参考库三算法同一接口） / 3.6.2 关键澄清（`predict`/`observe` 是"世界的节奏"不是"算法的结构"） / 3.6.3 三层模型 / 3.6.4 现状泄漏点清单 / 3.6.5 提案修法 / 3.6.6 判据。
> 按去重规则（见文首），此处**不复制**上述内容。

**本次问答独有的内容（DESIGN 未收录）——一处心智模型修正**：

不是"输入 `q_last` 和 `q_cur` 得到估计"，而是：

```
输入（每次调用给）:  量测流 (gyro/acc/...) + dt
内部状态（自己记住）: q_last + 算法特有的其他状态   ← 这就是 Estimator 要持有 solver_ 成员的理由

**困惑的根源（值得记住）**：把"算法内部结构"当成了"接口契约"。分清这两层，歧义自然消失。
