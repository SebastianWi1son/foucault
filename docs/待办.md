  1. **`integrate` 实为全局二阶，非文档所说"一阶欧拉"**：Richardson 自比较实测观测阶 **p = 2.039（常角速度）/ 1.978（时变 ω）**。原因：`normalize(q + ½q⊗(0,ω)dt)` 恰好消掉二阶项（纯四元数 x 有 x²=-|x|²）→ 与 `exp(½ω̂dt)` 差 O(|x|³)。→ 建议：DESIGN §1.5 与 `quat.hpp` 注释补一句"名义一阶、实测量化后全局二阶"，否则未来会按错误精度预算做决策（例如误以为需升 RK4）。
  2. **`inv_sqrt` 退化输入无定义域检查**：`inv_sqrt(0.0f)→2.97e19`（非 inf）、`inv_sqrt(-1.0f)→inf`、而 double 路径分别给 `inf`/`nan` → **float/double 行为不一致**。当前调用点均在受保护路径（`n2>0` / `n>0`）上，暂无后果，但属隐患。
  3. **`rotate` 快速展开式 ≠ `q v q*`（当 |q|≠1）**：实测 q=(1,0,0,0.30) 时输出模长 1.01607，而精确 `qvq*` 应为 |q|²=1.09，偏差 0.074 ≈ 7%。→ 这强化了"normalize 是正确性前提而非优化"的结论；也说明 `rotate` 的文档应写明"仅对单位四元数等价于 qvq*"。

### 评估方法论（非缺陷，但需记录）

- [ ] **只测了一半：缺"收敛速度"指标 → 只按回放调参会系统性偏向过低增益（2026-09-12）**：`replay` 只测稳态 RMSE，且从**近正确初值**出发（起始 roll/pitch 误差仅 0.40°/2.34°），**完全未测上电收敛速度**。实测 Kp 景观（基线回放 50 Hz，roll+pitch 合成 RMSE / 从 20° 偏差收敛到 1° 用时）：

  | Kp（Ki 同步降） | 回放稳态 RMSE | 收敛到 1° 用时 |
  |---|---|---|
  | 5.0（**项目默认**） | 2.61° | **0.59 s** |
  | 1.0 | 1.85° | 2.86 s |
  | 0.25 | 0.86° | 10.2 s |
  | **0.10** | **0.55°**（最优） | **未收敛** |
  | 0.03 | 1.19° | 未收敛 |

  已验证**不是初始瞬态造成**（后 80% 段 RMSE 与全段几乎相同）。原因：该数据集是动态载体轨迹，加速度计被运动严重污染 → 低增益天然占便宜。
  → **不可据此直接改 Kp**（真实场景有硬性上电对准要求，如云台对准/步兵落地）。需先补两项指标：**① 从错初值出发的收敛时间；② 高动态段的最坏误差（非 RMSE）**，再谈整定。

- [ ] **回放的 `dt` 时间语义未定义 → 评估可能含固定一拍偏移（2026-09-11）**：`predict` 无条件把状态推进 `dt`，但"推进后的状态对应哪一刻"完全由调用方对 `dt`/`gyro` 的定义决定，代码与文档都没写：
  - 若 `gyro_i` 是"上一周期平均"（多数 IMU 驱动如此）且 `dt` = 相邻帧间隔 → predict 后状态 = `t_i` 时刻，与 `rows[i].gt_` 比较**正确**
  - 若 `gyro_i` 是 `t_i` 瞬时值 → predict 后状态 = `t_i + dt`，比较**领先一拍**
  实测（把 CSV 的真值平移 k 个样本再算 RMSE，15000 帧）：k=+1 roll 2.121° / pitch 2.630°，优于 k=0 的 2.152° / 2.645°；但曲线极平（-0.08s→+0.8s 内仅变 0.15° = RMSE 的 7%，最低点在 k=+10），**只能确认方向、不能定量**。
  待办：明确 gyro 的时间约定并写入 DESIGN；**将来做 Mahony/Madgwick/EKF 三算法精度对比时必须统一**（否则比的是时序而非算法）。相关：`replay_nav2.cpp`。

- [ ] **P2-8 `predict` 命名与 DESIGN §1.6 的 `correct()` 承诺不一致（2026-09-11）**：DESIGN §1.6 把接口设计成 `predict(gyro,dt)` = "唯一固定的运动学" + `correct()` = "增益求解器可插拔（算法差异只在这里）"；但实际代码 **没有 `correct()`**——Mahony 把修正折进 `predict` 的 ω 里（`mahony.cpp` 的 `predict()` 内部），算法差异实际发生在 `predict` 内部。→ 门面的 `predict` 对 EKF 诚实（真·纯外推），对 Mahony 名不符实（它是"外推+修正"一体）。需在 DESIGN/CODE 显式写明：**门面 `predict` 的语义 = 时间推进（含该求解器自身的修正机制）**，并说明为什么 Mahony 拆不出独立的 correct 步。
- [x] **P2-9 replay 的时间约定未文档化 → 已核实（2026-09-11），降级为"文档待补"**：查参考库 `reference/IMU_Attitude_Estimator/demo/Test.cpp` 与 `reference/IMU_Attitude_Estimator/src/Mahony_Attitude.cpp`：参考库使用**与我们完全相同的约定**（`Run(measurements.row(i))` → 与 `groundtruth.row(i)` 直接比，不做时序补偿），且其 `deltaT` 也是构造时写死的 0.02。→ 本 replay 是忠实复刻，**不存在相对参考库的偏差**；k=+1 的微弱优势（roll 0.031°）远小于 k=+10 的 0.15° 且曲线极平，**不具备一拍时序偏移的形状**，故判为**不显著**。
  → 降级后的待办：仅在 `data/README.md` 写明约定（"gyro_i 按 deltaT 积分一步，积分后状态对应 t_i，与 gt[i] 直接比较"），并在 `replay_nav2.cpp` 头注释标注"与参考库一致"。**将来多算法对比时沿用同一约定即可。**
