## 1. 姿态解算的本质数学公式

### 1.1 与底盘公式的类比

底盘：`Wheels = J·(vx, vy, ωz)ᵀ` —— 静态代数映射，无记忆无积分。
姿态：**积分量**，本质是"微分方程 + 反馈修正律"（观测器），不是静态矩阵。

### 1.2 本质公式（所有算法的通用形式）

```
（1）过程模型（唯一、固定、与算法无关）：
     q̇ = ½ · q ⊗ (ω_meas − b)        ḃ ≈ 0
     矩阵形式：q̇ = ½·Ω(ω)·q

（2）观测模型（量测来源，可插拔）：
     z = h(q) = R(q)ᵀ · v_ref
     —— 加速度计：v_ref = g（重力矢量，定 roll/pitch）
     —— 磁力计  ：v_ref = m（地磁矢量，定 yaw）
     —— 外部参考：v_ref = 编码器/里程计/视觉给的航向

（3）修正律（算法的全部差异集中在这里）：
     q̂̇ = ½·q̂⊗(ω−b̂) + K · (z − h(q̂))          ← 本质公式
     b̂̇ = 增益律（Mahony 的 Ki·∫err / EKF 的状态更新）
```

- `z − h(q̂)` 是残差（实测重力方向 vs 预测重力方向的夹角）；
- `K` 是增益：Mahony=Kp 常数（叉积误差）、Madgwick=β 梯度步长、EKF=P⁻Hᵀ(HP⁻Hᵀ+R)⁻¹ 时变最优；
- **Kalman 与 Mahony 不是两类东西，是同一观测器方程下 K 的两种求法。**

### 1.3 为什么姿态没有静态公式

同一帧 (ω, a) 对应无穷多姿态历史 —— 姿态是微分方程的解，必须做成带记忆的状态估计器。

### 1.4 特例：2D 退化（gyro-z 小车方案 = 本质公式的一维退化）

```
预测：ψ̇ = ωz          （只积分 z 轴）
观测：ψ_ref（可选）
修正：ψ̂̇ = ωz + K·(ψ_ref − ψ̂)
K=0 → 纯陀螺积分（现状）；K>0 → 互补/一维 Kalman
```

三维公式与一维公式**数学结构完全同构** —— "一个核心覆盖 2D/3D"在公式层面成立。

### 1.5 姿态表示选型

| 表示 | 优点 | 致命缺点 |
|---|---|---|
| 欧拉角 | 直观、与云台轴系对应 | 万向锁；微分方程复杂 |
| 方向余弦矩阵 | 无奇异 | 9 参数 + 必须正交化 |
| **四元数** | 无奇异、4 参数、微分方程最简、计算最快 | 不直观；须归一化 |
| SO(3) 李群 | 理论最优雅 | 实现复杂，MCU 少见 |

四元数归一化是积分后必须做的一步；欧拉角只在**输出层**转换。

### 1.6 本质公式对架构的推导

```
predict(gyro, dt)                     —— 唯一固定的运动学
observe_vector(vec, ref, trust)       —— 6轴/9轴向量观测
observe_yaw(yaw_ref, trust)           —— 外部航向注入
correct()                             —— 增益求解器可插拔（算法差异只在这里）
```

## 2. 场景覆盖与产品分析

### 2.1 三个场景的真实需求

| 需求维度 | 地面寻迹小车 | 云台 | 立体步兵 |
|---|---|---|---|
| 自由度 | 1（yaw） | 2~3 | 3（地形冲击大） |
| 核心量测 | 陀螺 z 积分 | 三轴陀螺+加速度计(+磁) | 三轴陀螺+加速度计(+视觉) |
| 动态范围 | 低 | 高（1000°/s 量级） | 极高（弹道冲击） |
| 更新率 | 100~200Hz | 500Hz~1kHz | 500Hz~1kHz |
| 主要矛盾 | 零偏累积 | 动态跟随 vs 噪声 | 运动加速度污染量测 + 冲击后快速恢复 |

**三个场景运动学完全相同，差的是传感器配置与量测可用性 → "一个核心 + 配置档位"可行。**

### 2.2 关键约束①：可观测性（决定"通用"的天花板）

- 只用 6 轴 IMU，**绝对 yaw 永远不可观**（重力与 yaw 旋转轴平行）；yaw 只能靠陀螺积分（相对航向）；
- 参考库明证：`GyroBias[2]=0`（z 轴零偏不估）+ q3 修正强制置零；
- yaw 绝对参考只能来自外部（磁/GPS/视觉/编码器/里程计）→ **核心必须留"外部 yaw 参考注入"接口**；
- 加速度计在非静止/非匀速时不可信 → 6 轴精度上限取决于"量测仲裁"（静止检测+拒收）做得多好。

### 2.3 关键约束②：维度降级（2D ≠ 3D 的特例那么简单）

- 2D 模型：`ψ̇=ωz`；3D 模型：`q̇=½Ωq`；
- **陷阱**：把 3D 核心跑在小车上（ωx=ωy≈0），x/y 轴零偏与振动被积分 → roll/pitch 漂移 → 四元数归一化耦合污染 yaw；加速度计修正还会把振动当真拉回来；
- **必须显式支持降维模式**（见 §3.5），而不是靠"喂零值"隐式降维。

### 2.4 结论：一套核心全覆盖 —— 可行，但是"平台 + 模式"

```
┌─────────────────────────────────────────────────┐
│            通用姿态核心（与场景无关）               │
│  状态模型：四元数(+零偏) 或 单轴 yaw 模式           │
│  预测：   q̂̇ = ½·q̂⊗(ω−b̂)     （唯一固定部分）    │
│  修正：   K·(z − h(q̂))                           │
│  ┌─ 可插拔增益求解器 ─┐   ┌─ 可插拔量测源 ──────┐  │
│  │ Mahony / Madgwick │   │ 加速度计(6轴)       │  │
│  │ EKF / 单轴KF      │   │ 磁力计(9轴)         │  │
│  └──────────────────┘   │ 外部yaw参考(编码器/  │  │
│                         │ 里程计/GPS/视觉)    │  │
│  └──────────────────────┴─────────────────────┘  │
│  保护机制：静止检测 / 卡方检验 / 自适应增益 / 限幅   │
└─────────────────────────────────────────────────┘
        │                    │                    │
   profile: yaw-only    profile: gimbal      profile: infantry
```

### 2.5 产品分析

**市场空位**：现有开源库里没有"一个内核、多算法插拔、2D/3D 模式、跨平台纯 C++、零依赖"的组合档位：
- x-io 最干净但单算法；PX4 ECL 最全但为无人机定位场景设计、移植成本极高；6-Axis-AHRS 接近但写死 RoboMaster 场景；参考库绑定 STM32+ARM DSP。

**差异化定位**：姿态解算界的"可移植数学内核"（类比 CMSIS-DSP 之于数字信号处理）：
- 纯 C++17 / 零动态内存 / 无 OS 依赖 / header-only 可编译；算法可插拔；维度模式 + 量测源配置；平台层只留 3 个钩子（时间戳、数学函数、日志）。

**风险清单**：① 可观测性天花板（宣传须诚实：绝对航向需外部参考）；② 验证成本高（需数据集+真值+转台）；③ EKF 调参门坎（需 Allan 方差工具+默认参数）；④ 与闭源商业库（MotionFX）的竞争取决于生态与口碑。

## 3. 设计决策记录（含 C++ 构建等问答结论）

### 3.1 C++ 构建影响（已定：C++17）

| C++ 特性 | 用途 | 嵌入式纪律 |
|---|---|---|
| class + 句柄式实例 | 消灭全局单例 | 允许，核心价值 |
| 模板（Scalar float/double、DoF） | 一处实现双精度/单精度、2D/3D 复用 | 允许，零开销 |
| 运算符重载（四元数） | 数学表达贴近公式 | 允许，注意内联无临时对象 |
| 虚函数/策略模式 | 算法可插拔 | 允许，1kHz 下每帧几 ns 可忽略 |
| STL | — | **默认禁用**，或提供 FOULCAULT_NO_STL 开关 |
| 异常/RTTI/动态内存 | — | **禁用**（-fno-exceptions -fno-rtti，零 malloc） |
| if constexpr / constexpr 配置 | 编译期裁剪 | 允许，替代 C 宏 |

### 3.2 六轴 vs 九轴（设计结论：量测源配置差异，非架构差异）

| | 6 轴 | 9 轴 |
|---|---|---|
| roll/pitch | 可观 | 可观 |
| yaw | **不可观**（积分漂移） | 可观（地磁定航向，需校准） |
| 动态可靠性 | 加速度计被运动加速度污染 | 磁力计受电机磁场/铁磁体干扰 |
| 附加成本 | 无 | 椭球/软硬磁校准 + 干扰检测 |

**对核心的 5 个影响**：① 状态向量不同（9 轴可把磁场放进 EKF 状态在线估计）；② yaw 处理策略不同（6 轴=外部注入接口+接受漂移；9 轴=磁观测）；③ 磁力计需要自己的可信度仲裁（模长/倾角/残差门限）；④ 校准管线是独立模块（坏磁数据比没磁更糟）；⑤ 计算量差异可忽略。

**场景选型**：小车 = 6 轴 + 里程计 yaw；云台 = 6 或 9 轴可选；步兵 = 6 轴为主（全金属+大电流电机，磁力计实测报废）+ 视觉可选。

### 3.3 外部 yaw 真相源清单

**产品传感器配置（2026-08-30 用户确认）**：里程计 **确定有**；视觉 **待定**；磁力计 **大概率没有**。→ 后续设计以"6 轴 + 外部 yaw 注入"为主线：yaw 真相源 = 轮式里程计（地面小车）/ 云台编码器 / 视觉（若上）；9 轴磁力计方案降为可选分支，优先级降低。

| 来源 | 原理 | 精度/频率 | 可用条件 | 适用场景 |
|---|---|---|---|---|
| 磁力计 | 地磁水平分量 | 1~5°（校准后） | 无强磁场干扰、需椭球校准 | 云台、室外车 |
| 轮式里程计 | 左右轮速差积分 | 短时好，打滑发散 | 地面无打滑 | 地面小车首选 |
| 云台/关节编码器 | 电机编码器 | 0.1° 级 | 有固定基座参考 | 云台相对 yaw |
| GPS 航迹/速度方向 | 对地速度矢量 | 需速度 >2~3m/s | 室外开阔、运动中 | 室外车、无人机 |
| RTK 双天线 | 载波相位差 | 0.1~0.3° | 室外、贵 | 无人车/农机 |
| 视觉（AprilTag/VIO） | 视觉定位航向 | 0.1~1° | 有纹理/标签 | RM 步兵、室内车 |
| 光纤/激光陀螺 | 感知地球自转 | 0.01°/h 级 | 成本 >1 万元/轴 | 舰船/导弹，MEMS 不可行 |

**接口含义**：`observeYaw(yaw_ref, trust)` 一等公民；多源可同时注入（EKF 天然支持多量测）；无真相源时优雅降级为纯积分并标注"相对航向"。

### 3.4 多算法可插拔（已定：可行）

- 理论依据：本质公式中算法差异只在 K；
- 例证：gaochq 一框架三算法、Library-SensorFusion 四算法、PX4 的 attitude_estimator_q 与 EKF2 并存；
- 实现：运行期策略（虚函数，推荐）或编译期策略（模板，零开销但运行期不可换）；
- **三条铁律**：① 数学内核共享不插拔；② 插拔分两层：状态模型层（2D/3D，模板 DoF）> 增益求解器层（Mahony/EKF/KF）；③ 每个可插拔件携带自己的配置与状态（对象/结构体，不是裸函数指针）。

### 3.5 显式降维（Explicit Dimension Reduction）

**定义**：核心主动把状态模型裁剪到应用的真实自由度，而非靠"喂零值"隐式实现。

2D 完整退化：`预测 ψ̇=ωz / 观测 ψ_ref / 修正 ψ̂̇=ωz+K(ψ_ref−ψ̂)`。

**为什么必须显式**（隐式降维的坑）：把 3D 核心跑 2D 平台 → ① x/y 零偏与振动被积分，roll/pitch 漂移；② 四元数归一化耦合污染 yaw；③ 加速度计修正把振动当真拉回来；④ 调参无物理意义。显式降维在模型层解决：状态只有 ψ，从根上消除无效自由度。

**2.5D 中间形态**：3D 状态 + roll/pitch 量测降权或限幅（云台底座/步兵地形感知场景的档位）—— 不是 2D 也不是满 3D。

### 4.2 核心状态机

```
 UNINIT ──首次观测到位──► CONVERGING ──收敛判定──► CONVERGED ◄──┐
                          ▲                        │           │
                    异常/发散触发            观测源失效（降级不重置）│
                   （卡方连续超限/            ┌───▼────┐         │
                    协方差爆炸）              │DEGRADED│─────────┘
                                            │(仅预测/降权/│
                                            │ 相对航向标记)│
                                            └──────────┘
```

关键规则：**观测源失效 ≠ 滤波器失效** —— 磁力计被干扰时自动降级为"相对航向"并打标志，不拉歪 yaw、不重置。

### 4.4 核心接口（概念签名）

```cpp
namespace foucault {

template <typename Scalar = float, int DoF = 3>   // DoF: 1=2D, 3=3D(含2.5D)
class Estimator {
public:
    struct Config;                                // 噪声/增益/阈值/profile 预设

    void reset(const Config&);                    // 支持多实例，无全局状态
    void predict(Scalar dt, const Vec3<Scalar>& gyro);      // IMU 速率
    void observeAccel(const Vec3<Scalar>& accel, Scalar trust);   // 6轴
    void observeMag  (const Vec3<Scalar>& mag,   Scalar trust);   // 9轴
    void observeYaw  (Scalar yaw_ref, Scalar trust);              // 外部真相源

    Quat<Scalar>        quaternion() const;
    void                euler(Scalar& roll, Scalar& pitch, Scalar& yaw) const;
    const OutputStatus& status() const;   // 收敛/降级/相对or绝对航向/innovation
};

struct GainSolver {                             // 可插拔（策略模式）
    virtual ~GainSolver() = default;
    virtual void reset() = 0;
    virtual void correct(State&, const Measurement&) = 0;
};

}
```
